C. Edge and corner cases

  • Long names, emails, services wrap inside the card; nothing scrolls sideways (checked at 360 / 384 / 412 px during the build).
  • No phone: no call link. No email / message: shown empty, as desktop does today.
  • Changing a status: the pill greys out with the small spinner while saving, as today. Cancel in the popup keeps the old status.
  • Deleting: the button shows the spinner, then the page reloads (today's behaviour, kept).
  • Date filter (Today / 7 / 30 days), per page (5 / 10 / 25 / 50), search: same as desktop.
  • Phones sideways and tablets (up to 1023 px): the same cards. 1024 px and up: today's desktop table, unchanged.
  • Same data as the ERP: a status changed here shows in the ERP's Enquiries page and the other way round.

D. Existing bugs found while checking (these affect desktop too)

Found in today's website admin, checked live on DEV. Please tell me which to fix together with the phone layout. My recommendation: #1, #2, #3, #7 and #8 (small, safe fixes). The rest only if you want.

#1 CRITICAL: data page goes blank with more than 10 submissions. The page counter uses a value that doesn't exist ("startIndex is not defined"). With 11+ submissions in a clinic (more than one page), the whole Dental Metrix / Meditouch data page turns white, on phone and desktop. Reproduced with 16 test rows (no data saved). If LIVE has more than 10 for a clinic, the live admin page is broken right now.
#2 Delete popup button says "Update Status" (orange) instead of Delete (red).
#3 Dashboard "Recent Submissions" reads wrong field names: the service line is empty and every enquiry shows the Meditouch icon.
#4 "Scheduled Today" counts all scheduled enquiries, not just today's.
#5 Conversion Rate would show "NaN%" when there are no submissions.
#6 Date filter only filters the rows on the current page, not all submissions.
#7 Popup dark background leaves a thin white strip at the top of the screen.
#8 Details popup: Email and Phone overlap when the email is long (fixed on phones by screen 8; on desktop only if very long).
Security (separate task, not part of this work): the admin login page itself shows the username and password ("Demo Credentials" box), they are also written in the website's own code, and the database lets the public website key read, change and delete all enquiries. Recommend fixing separately, carefully on LIVE.
